# 评估协议：规则 v3 与留出集评估（2026-10-28 起草，冻结前可改，冻结后只追加偏差记录）

## 1. 目的

现有规则（`CanonV2.lean`，10-08 冻结）是在 ProofNetVerif test 的 300 对子集上开发的，全集上的错误接受全部落在子集之外
（论文附录 "What was fixed in advance"）。本协议规定：v3 规则只在 test 上开发，再在从未使用过的 ProofNetVerif valid 上
一次性评估，v2 与 v3 同时报告。

## 2. 数据

- **开发集**：ProofNetVerif test，可用的 1,140 对（694 不等价、446 等价）。所有规则设计、消融和调参只用这部分。
- **留出集**：ProofNetVerif valid，原始 2,300 对（标签：632 等价、1,668 不等价）。截至起草时，没有任何实验脚本读取过
  valid 的内容；`inspect_proofnetverif.py` 只打印过它的表结构和标签计数。
- **加锁**：`realdata.proofnetverif("valid")` 只有在 `data/real/v3_freeze.json` 存在、且进程环境变量 `PNV_VALID_UNLOCK`
  等于其中记录的冻结提交时才能读取。冻结前不查看 valid 的任何命题、规范化结果或判定。
- **冻结后的第一步**（预先规定）：核对 valid 与 test 的 `stmt_id` 交集；若有重叠题目，主分析剔除这些题目，并单独报告。
- 标签：valid 只有 ProofNetVerif 原标签（SemantEq 的复核只覆盖 test），所有结论注明"按原标签"。

## 3. 比较对象（同一证明器、同一预算）

| 臂 | 说明 |
|---|---|
| closed | 闭合等价（四个闭合目标），复现 RQ1 |

- 判定函数：`paper_check.verdict`（含闭合反驳即 reject、缺重组证书即 unknown 的规则），冻结时记录其提交。

每条规则在 test 上必须满足：
1. 299 个表面重述（`e5_meta.py`）不产生相互矛盾的判定；
2. 规则敏感性测试（`k12_canon_sens.py`）中，有方向证书（`npimp`/`rs`）的 reject 不改变；
3. 所有判定仍以两个重组证书为前提。

在 test 上使错误接受增加超过 3 个的规则，不进入 v3。

## 5. 指标与预先设定的假设（全部在 valid 上、按原标签）

主要指标：不等价对上的错误接受率（accept，不含 residual）；等价对上的接受率；判定覆盖率（accept + reject）；不等价对
reject 中已定位的比例；reject 精度。均给出 Wilson 95% 区间；配对比较用精确 McNemar 检验。

- **H1（复现 RQ1）**：同一证明器下，closed 的错误接受显著多于 v2（McNemar，双侧 α = 0.05）。
- **H2（v2.1 的覆盖收益）**：v2.1 在等价对上的接受率高于 v2（McNemar，单侧 α = 0.05），且错误接受率的增加不超过 1 个
  百分点（非劣效界）。
- **定位（描述，不作检验）**：报告 v2 与 v2.1 已定位 reject 的个数和比例。R0 新增的 reject 全部来自闭合反驳，按定义
  未定位，所以比例必然下降、个数按构造不会减少；原先的 H3（"比例不低于 v2"）因此没有信息量，在 test 上验证打分代码时
  发现（10-28，冻结前），改为描述性报告。
- **H4（开发集偏差）**：v2 在 valid 上的错误接受率与它在 test 中 300 对子集之外的 840 对上的错误接受率之间没有显著差异。

**决策规则**：只有 H2 成立，v2.1 才替换 v2 成为论文主判据；否则论文以 v2 为主，v2.1 作为负结果在附录报告。无论结果如何，
三臂结果全部报告。

- 冻结后不修改规则、预算、判定函数和分析脚本。确需修改的，在本文件记录原因，所有受影响的结果标为探索性。
