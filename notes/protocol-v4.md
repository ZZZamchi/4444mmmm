# 评估协议 v4：规范形与搜索式对齐（2026-11-10 起草，冻结前可改，冻结后只追加偏差记录）

## 1. 目的

导师反馈（11-10）：留出集上正确候选的接受率只有 57.7%，错误接受低但正确接受也低，在实际的自动形式化里用不上。
建议从规范形和对齐入手，并对变量做置换比较。v4 只改规范化、对齐和判定规则，不增加模型预算：规则只在 test 上开发，
再在 valid 上按本协议评估一次。

valid 已在 v3 中使用过一次（closed、v2、v2.1 三臂）。本轮开发没有读取 valid 的任何逐对内容，只看过 v3 已公开的汇总数
（`data/real/v3/valid/scores.json`）。因此 v4 仍按预先登记的方式在 valid 上评估，报告时注明这是该集合的第二次使用。

## 2. 数据

- **开发集**：ProofNetVerif test，可用的 1,140 对（694 不等价、446 等价），基线为 v2.1 在 G5（Opus）运行上的判定。
  另用 SemantEq 的人工复核（只覆盖原标为等价的对）给出更正标签下的数字，作为参考，不参与规则取舍。
- **留出集**：ProofNetVerif valid，可用的 1,478 对（953 不等价、525 等价），与 v3 相同；基线为 v3 已冻结的 v2.1 结果。
- **加锁**：`k22_align.py --split valid` 只有在 `data/real/v4_freeze.json` 存在、且环境变量 `K22_VALID_UNLOCK`
  等于其中记录的冻结提交时才运行。

## 3. 规则（`ExperimentsMathlib.CanonV4`，开关 `univ0m,align`；判定规则 L、NF）

| 编号 | 内容 | 性质 |
|---|---|---|
| U | 两条命题的宇宙参数不一致时（`Type` 对 `Type*`），把所有宇宙参数实例化为 0 | 规范形；证书只覆盖宇宙 0 的实例 |
| A | 对齐由搜索而不是贪心给出：在类型相容的变量对应中，取对齐变量最多的；同样多时取两边假设逐条重合（模 `>`/`<`、`≥`/`≤`、`≠`/`¬=`、等式方向）最多的，再取共享子项最多的；仍相同则保留 v2 的选择 | 对齐；在任何证明之前、只由两条命题决定 |
| L | 一侧完全对齐、另一侧的剩余部分不含假设时，accept 视为局部的（剩余部分是对另一侧没有的变量量化的结论） | 判定规则 |
| NF | residual 的 `acc` 由规范形同一性证出时记为 accept：两边用一组与内容无关的逻辑和顺序引理改写后逐字相同 | 判定规则；与 R3 同属内涵证据 |

不纳入：两侧都有剩余部分的局部性（test 上 +14 个错误接受）；推广关系 R5（候选上下文更一般，需要新的单向判定，
属于另一项研究）；K16、K19 的目录规则（收益小且有伪差异）。

每条规则在 test 上须满足：错误接受增加不超过 3 个；重命名和保义打乱测试（第 5 节）中，已接受的等价对的目标变化
不多于 v2。

## 4. 比较对象（同一证明器、同一预算）

| 臂 | 说明 |
|---|---|
| v2.1 | v3 冻结的结果，原样复用 |
| v4 | v2.1 + U + A + L + NF。目标未变的对沿用 v2.1 的证明；目标改变的对重新证明：固定 tactic、R0 两档、R3、每个未决组件目标一次 Opus 提议、一轮修复；最后对 residual 和 unknown 运行 NF |

同时报告消融：只加 L、NF（不改目标）；只加 U、A（不加判定规则）。

## 5. 指标与预先设定的假设（valid，原标签）

主要指标同 v3：不等价对上的错误接受率；等价对上的接受率；Wilson 95% 区间；配对比较用精确 McNemar 检验。

- **H5（覆盖率）**：v4 在等价对上的接受率高于 v2.1（McNemar，单侧 α = 0.05），且不等价对上的错误接受率增加不超过
  1 个百分点。
- **描述**：目标改变的对数；各臂的判定分布；新增错误接受逐条列出。
- **稳健性（描述，只用 Lean）**：对每个候选做两种保义变换：全部绑定变量改名；同类型的相邻数据变量块倒序加改名。
  报告对应关系或组件目标发生变化的对数，v2 的贪心对齐与 A 分别报告。

**决策规则**：H5 成立，v4 成为推荐判据，论文并列报告 v2.1 与 v4；否则 v4 作为负结果写入附录。无论结果如何，
各臂全部报告。

## 8. 开发日志（test，冻结前）

- **11-10，诊断**：v2.1 未接受的 169 个等价对中，96 个被 SemantEq 人工复核改判为不等价；按复核标签，真等价的 350 对
  中 v2.1 接受 274（78.3%），闭合等价 346（98.9%）。真正的缺口 74 对：residual 52、unknown 17、reject 5。residual 的
  主要来源：宇宙层级不一致使对齐在第一个变量就停下（如 `{α : Type}` 对 `{X : Type*}`）；候选结论多一层量词
  （`f = g` 对 `∀ x, f x = g x`）；没有绑定变量的封闭命题；推广或特化（ℕ 对可数 ι、一般域对 ℝ、`Ring` 对 `CommRing`）。
- **11-10，置换（导师建议 2）**：只在贪心前缀内置换（旧开关 `perm`）在 test 上改变 5 对，全部不等价；把候选全部变量
  改名，贪心对齐的对应关系只在 15 对上改变，说明 ProofNetVerif 中候选与参考的变量名基本一致。保义打乱（同类型相邻
  变量倒序加改名）改变 418 个候选：贪心对齐下 413 对的组件目标改变，其中 123 对是 v2.1 已接受的等价对；`perm` 为 242
  对、40 对。原因是类型依赖的连锁（`X ↦ β` 之后 `f : X → Y` 配不上），所以改为在对齐本身中搜索（A，开关 `align`）：
  改名后对应关系改变 0 对；打乱后完全对齐的对数不变（等价对 335、不等价对 264，贪心为 295、242）；组件目标改变 178 对，
  其中 v2.1 已接受的等价对 7 对。真实数据上 A 改变 6 对，全部不等价。
- **11-10，局部性**：两侧都有剩余部分也算局部时，test 上等价对 accept +6、错误接受 +14（14 对都是两侧类型不同、
  剩余部分是两条无关的真命题，如 `ZMod n` 对 `ℤ` 上的结合律），放弃；只允许一侧有剩余时 +6、+0，采用为 L。
- **11-10，NF**：在 431 个 residual 或 unknown 对上证出 7 个（等价对 residual→accept 5、unknown→accept 2），不等价对 0。
- **11-10，合计（`univ0m,perm` + L + NF，Opus 之后）**：等价对 accept 277 → 300（62.1% → 67.3%），错误接受 14 → 15；
  新增的 1 个是 `pnv-test-682`（候选多一个度量空间本来就满足的 `[T2Space X]`，K16 已记为疑似标签错误）。按 SemantEq
  标签：297/350（84.9%），错误接受 18/790（2.3%）。Opus 调用约 $8，连接重置较多（41 次失败尝试）。
- **11-10 21:30，暂停**：导师给出目标：正确命题的接受率要 80% 以上，至少不能被闭合等价拉开大的差距。按原标签这个目标
  高于任何可靠判据的上限：test 的 446 个"等价"对里 96 个经人工复核不等价，不接受不等价对的判据最多 350/446 = 78.5%，
  闭合等价的 86.1% 里含 38 个这样的对。所以 80% 应按复核后的标签衡量：v4 候选 84.9%，闭合等价 98.9%。
  暂停时 `k22_align.py run "univ0m,align"` 停在 Opus 阶段（58 对未决，模型回复与 Lean 结果有缓存）。
- **11-11，恢复并定稿（`univ0m,align` + L + NF）**：H5 在 test 上成立（23 对 0，单侧 p ≈ 10⁻⁷，错误接受 +0.14 个百分点，
  新增的 1 个是 `pnv-test-682`）。等价对 accept 277 → 300（62.1% → 67.3%）；SemantEq 标签下 274 → 297（78.3% → 84.9%），
  错误接受 17 → 18。消融：只加 L+NF 到 290/287；只加 U+A 到 281/278。搜索式对齐相对旧的前缀内置换不改变主数字，
  但改名稳健性从 15 对对应关系变化降到 0，打乱后完全对齐的对数与未打乱相同。剩余 51 个真等价未接受：residual 且部分
  对齐 23、完整对齐但预算不足 14、无绑定变量的封闭 residual 8、reject 5、其它 1；其中 48 个闭合等价已证出。不纳入的
  剩余方向：推广关系（约 20 对，需新判定语义）、封闭命题的内涵证据、更强证明器。

  部分上坍缩；test 上 L 的 12 个新增接受全为等价对，没有暴露这一点。限制 L（例如要求剩余部分在对齐输入上不取常值）
